# Ferry — Testing

*Policy + how-to. Update when suites, servers, or process change.*

## Policy (user-mandated, CLAUDE.md rule 2)

Every milestone ships, in the same milestone as the code:
1. **Unit tests** for all new FerryCore logic → `FerryKit/Tests/FerryCoreTests`.
2. **Integration tests** exercising the feature end-to-end against real servers →
   `FerryKit/Tests/FerryIntegrationTests`.
3. UI milestones additionally get **XCUITest** smoke tests (`FerryUITests/`) plus a manual
   checklist against the approved mockups (docs/DESIGN.md).

A milestone may not be presented for review until the app builds and all suites pass.

## Running

```sh
testinfra/start.sh                 # bring up test servers (required for integration tests)
cd FerryKit && swift test          # unit + integration
swift test --filter FerryCoreTests # unit only

cd .. && xcodebuild -scheme Ferry-Direct -destination 'platform=macOS' test  # UI tests
testinfra/stop.sh
```

- Integration tests **skip** (with instructions) when servers are down. Set
  `FERRY_REQUIRE_TEST_SERVERS=1` to turn absence into failure (CI usage).
- **UI tests one-time setup**: `sudo DevToolsSecurity -enable` in a real terminal
  (otherwise: "Timed out while enabling automation mode"). Done on this machine
  2026-07-05 — only needed again on a new dev machine.

## M9 additions (112 kit tests + 4 UI, all green)

- `FerryCoreTests/TransferEngineResumeTests` (unit, InMemoryFileSource): `.ferrypart`
  resume byte-exact, restart mode, stale/oversized partial discarded (GC), finalize
  replaces confirmed destination, upload resume/restart, transient retry (succeeds on
  attempt 3, exhausts, deterministic errors don't retry, retry resumes own partial),
  manual resume of failed items, pause running/queued + resume byte-exact, cancel of
  paused, lazy directory tree copy, folder merge preserving unrelated children.
- `FerryCoreTests/ConnectionSupervisorTests` (unit, fake connection): keep-alive pings,
  ping-failure → reconnect → recovery, backoff walks attempts then `.lost` + manual
  reconnect, `noteFailure` immediate + deduplicated cycles.
- `FerryIntegrationTests/SFTPRobustnessTests` (Docker SFTP): **kill mid-transfer**
  (server-side `pkill` of the session; 32 MiB file seeded via `docker exec dd`) →
  ERROR → reestablish + resume → md5-verified byte-exact, `.ferrypart` lifecycle;
  retry policy self-heals across a reconnect; paused upload resumes from remote size;
  folder upload/download round-trip; mkdir with intermediates; supervisor detects a
  dropped link and reestablishes it. Caveats in ADR-014: never close the local
  SSHClient mid-read (NIOSSH fatalError); test timeouts must race a timer, not check
  deadlines on event arrival.

## Suite inventory (M1–M8)

- `FerryCoreTests` (unit): `FerryVersionTests`, `ConnectionProfileTests`,
  `ConnectionLibraryTests` (tree ops, Codable contracts), `CredentialVaultTests`
  (account-name contract).
- `FerryIntegrationTests`: `TestServerReachabilityTests` (SSH banner + FTP greeting),
  `ConnectionStorePersistenceTests` (real filesystem, temp dirs),
  `CredentialVaultKeychainTests` (REAL Keychain, test-only service, self-cleaning),
  `ReachabilityProbeTests`, `LocalFileSourceTests` + `SecurityScopedBookmarkStoreTests`
  (real filesystem), `SFTPSourceTests` (M6: real SFTP — auth, listing, stat, typed
  errors, byte-exact offset/multi-chunk downloads), `SFTPTransferTests` (M8: engine
  round-trips local↔SFTP byte-exact, concurrent uploads, cancel-mid-upload, write
  resume contract), `SFTPWriteProbeTests` (upload size ladder 64 KB–2 MB with per-size
  timeout — regression guard for wedged writes).
- `FerryCoreTests/TransferEngineTests` (M8, unit): byte-exact copy with progress via
  `InMemoryFileSource` fake, concurrency cap + near-FIFO start order, cancel of queued
  and running items, failure frees the slot, snapshot replay for late subscribers.
- `FerryUITests/FerryUITests` — launch + empty state, editor sheet open/cancel,
  create-connection flow (M4), and the M7 end-to-end walk-through: create a connection
  to the Docker SFTP server through the UI, connect via the password prompt, verify the
  remote pane lists the server, disconnect (skips itself when the server is down).
  **Isolation**: the app honors `FERRY_DATA_DIR` (connections.json location) and
  `FERRY_KEYCHAIN_SERVICE` env vars; UI tests set both, so user data and the real
  Keychain service are never touched.
