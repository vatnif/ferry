Review notes — Main window

  1. Sidebar holds the connection manager: folders (Work, Clients…) expand/collapse, connections show a protocol badge, drag to reorganize. Double-click connects in the current tab; ⌘-double-click opens a new tab. Right-click gives Edit / Duplicate / Delete / New Folder. Below it, "This Mac" holds local favorites.
  2. Tabs — one per connection; green dot = connected, grey = disconnected. The sidebar is shared across tabs.
  3. Panes — local always left, remote right. Both are the same component: sortable columns, breadcrumb path bar (clickable), per-pane hidden-files toggle (👁) and overflow menu (⋯). The remote pane adds Permissions and Owner columns. Drag rows between panes (or from Finder) to queue transfers.
  4. Transfer queue docks at the bottom, collapsible to a single summary row. Each row: direction, name, source → destination, progress, speed, ETA, pause/cancel. The "RESUMED" badge marks a transfer continued from a partial file.
  5. Toolbar — Upload/Download act on the selection; Tunnels and Terminal open screen 4 and the external terminal. The filter field filters the focused pane as you type.
  6. Status bar — connection state, endpoint, latency, active tunnel count.
  7. Sync browsing (approved) — the "🔗 Linked" toolbar toggle. When enabled, the current paths of both panes become anchor roots; entering or leaving a folder on one side mirrors on the other when a same-named folder exists there. If the folder is missing on the other side, that pane stays put and its path bar flashes briefly (the link is kept, not broken). Turning the toggle off returns both panes to independent navigation. Link state is per tab and shown in the status bar.

Review notes — Connection sheet

  1. Protocol segmented control adapts the form: FTP/FTPS hide the auth-method row (password only) and swap port defaults (21/990); SCP shows the same auth options as SFTP.
  2. Authentication — Password (Keychain), SSH Key (file picker + optional passphrase, passphrase also in Keychain), or SSH Agent (Direct build only; hidden in App Store build).
  3. Keychain hint is always visible — the security story is a selling point, so we say it in the UI.
  4. Test Connection runs live and reports success/failure inline, including host-key acceptance (screen 3) if the host is unknown.
  5. Advanced is collapsed by default for a lightweight first-run experience.
  6. An Import… button (bottom-left of the connection manager, not shown here) will pull from ~/.ssh/config in v1, FileZilla/Cyberduck in v1.x.

Review notes — Host key prompts

  1. First contact (top) — standard TOFU flow; "Remember" is on by default; fingerprint is selectable for out-of-band comparison.
  2. Changed key (bottom) — deliberately alarming; the safe action is the primary button, the dangerous one requires an extra confirmation ("…") and is styled as destructive.
  3. Keys accepted here go to Ferry's own host-key store; we can also read the user's OpenSSH known_hosts to pre-trust hosts (never write to it).

Review notes — Tunnel manager

  1. Three forward types: Local (local port → remote destination), Remote (remote port → local destination), SOCKS (dynamic proxy).
  2. Tunnels are saved on the connection profile; toggles work live while connected, and "auto-start" brings them up with the session.
  3. Status column shows live connection counts. Errors (port already in use, remote refusal) appear inline in that column in red.
  4. Tunnels reuse the existing SSH session — no second login. Reached from the toolbar "Tunnels" button or the connection's context menu.

Review notes — Settings

  1. Tabs planned: General (default local folder, appearance, reopen behavior) · Transfers (shown) · Keys (SSH key list, generate/import, agent toggle) · Terminal (choose Terminal.app / iTerm2 / custom command) · Advanced (logging, known-hosts management, experimental flags).
  2. Resume policy defaults to automatic — resume is a headline feature, so the default shows it off.
  3. Conflict policy defaults to Ask, with a "apply to all" option in the conflict dialog itself (dialog to be mocked in M7 if you want it).
  4. Bandwidth limit and checksum verification are v1.x features — included in the mockup so the layout has room, shipped disabled/hidden if the milestone slips.
  5. General / Keys / Advanced tabs added for M16 (2026-07-19, ADR-025) — these were only sketched in note 1 at M0; the three window mocks above are the proposed layouts. All wire in v1 per the user's decision: General (default local folder, Light/Dark/System appearance, reopen-last-connections) · Keys (list/generate/import SSH keys, ssh-agent shown disabled per ADR-017, Ferry known-hosts management) · Advanced (logging level + reveal, experimental-features flag). Sign-off pending.
  6. Transfers tab, v1.x rows: bandwidth limit + checksum ship visible-but-disabled ("v1.x") rather than hidden, so the layout matches the mockup and the roadmap is legible. Overwrite/Skip/Rename conflict presets and the interrupted-policy segmented control become functional in M16.

Review notes — App icon

  1. Recommendation: A, with B as runner-up if you want the function visible in the mark. C abandons the Ferry name story; D reads as a help/support symbol.
  2. These are direction concepts, not final artwork. macOS expects a 1024 px master with the rounded-square shape drawn into the artwork (with standard margins) and an .icns/asset-catalog set down to 16 px — produced in M17, ideally with a designer pass.
  3. The chosen concept ships as the development icon from M1 so test builds are recognizable in the Dock.
  4. The icon's gradient becomes the brand accent already used across the mockups (sea-teal #0d6e8c light / #35b3d4 dark); choosing C would shift the brand to navy + cyan.

Review notes — Embedded terminal (M15.5, approved 2026-07-18)

  1. Placement — the default is a collapsible panel docked below the panes, above the transfer queue (both can be open; each collapses independently) — the payoff of embedding is a shell next to your files. Height is draggable at the panel's top edge; state (open/closed, height, docked/windowed) is per connection tab.
  2. Pop-out (⧉) — moves the same live shell to its own window (third mock): the SSH session and scrollback are untouched, so a running tail -f survives the move. "⇤ Dock in Window" reverses it. Precedent: the tunnel manager is already a per-connection auxiliary window.
  3. One button, one setting — the existing toolbar Terminal button (accent-filled while the panel is open) dispatches on Settings ▸ Terminal: built-in opens this panel; Terminal.app / iTerm2 / custom command keep the M15 external hand-off. Built-in is the default on macOS 15+.
  4. Terminal-only connections — an Open Terminal item in the sidebar profile context menu (SSH profiles only) opens a shell without connecting the browser, honoring the same setting: built-in → the standalone window (third mock, with "Dock in Window" hidden — there is no browser tab to dock into); external → the M15 hand-off. Same host-key + credential flow as a normal connect.
  5. SSH profiles only — the Terminal button and the Open Terminal menu item appear for SFTP/SCP connections and are absent for FTP/FTPS (like Tunnels; FTP has no shell).
  6. Session & credentials — every terminal (panel or window) is its own SSH session with the same host-key trust and the resolved credential: no second password prompt, nothing typed or displayed is ever logged, scrollback lives in memory only.
  7. Lifecycle — the shell starts when the panel/window first opens; exit (or a dropped session) shows the ended state (second mock) with Restart Session. Closing the panel (✕) or the window terminates the shell after a confirm if a command is running; disconnecting or closing the tab terminates a docked terminal silently (a popped-out window stays — it owns its session).
  8. macOS 15+ only (same SSH-library gate as SCP): on macOS 14 the built-in option is disabled in Settings with a "Requires macOS 15" explainer — Direct builds fall back to Terminal.app; the App Store build (which has no external option) disables the toolbar button and menu item with the same explainer.
  9. App Store build — the three external choices are hidden entirely (launching other apps is Direct-only); built-in is the only and default behavior.
  10. Appearance — the terminal follows the app theme (light/dark) with the standard ANSI palette; SF Mono, size configurable. Check both themes with the toggle.
  11. Scope fence — Ferry's terminal is a convenience, not a terminal app: deliberately no terminal tabs, split panes, color themes, or keybinding editors — font and scrollback only. Recorded in ADR-023 so scope stays bounded.
